## 2. 原生客户端、依赖与请求通道

`android-native/`已建立，单`app`模块，Kotlin/Compose；旧`android/`保留历史。applicationId=`dev.local.catleaf.nativeapp`、显示名猫页、minSdk=29；不卸载用户包。沿用锁定兼容版本，不为本次变更升级依赖。Node/npm继续服务后端/旧Web，不参与原生UI打包。

| 能力 | 选择 | 必须验证 |
| --- | --- | --- |
| UI/状态 | Compose、ViewModel、StateFlow、协程；单一明确的数据访问路径 | IO/解析不阻塞主线程，列表 key 稳定，旋转/进程恢复不重复触发付费请求 |
| 数据 | Room / SQLite，schema 导出入库、显式迁移 | 事务、杀进程、失败回滚、升级；禁止 fallbackToDestructiveMigration |
| 普通设置 | DataStore | 主题/字号/非敏感配置；不含 API Key |
| 凭据 | Android Keystore 生成 AES-GCM 加密密钥；凭据密文与随机唯一 IV 存应用私有 no-backup 区域 | API Key 是被加密数据，不直接当 Keystore 密钥；重启可解密，失败保留其他数据并要求重新配置，禁止明文回退 |
| 网络 | OkHttp，实例/AI/公开抓取按目的地限定请求头 | 取消、超时、限额、TLS、重定向；不全局添加凭据拦截器 |
| 正文 | Android WebView + jsoup Cleaner 的明确 allowlist | RSS/提取共用净化；不执行 JS；外链和资源请求独立约束 |
| 系统能力 | 原生返回/Insets、Activity Result 文件选择、SAF、FileProvider/分享、系统浏览器能力 | 不申请全盘权限；屏幕旋转/键盘/读屏实际检查；不引入后台框架 |

先使用平台与既有依赖；新增库只解决已确定需求。Room/OkHttp 外不再预建另一个数据库/HTTP 抽象平台；需要 JSON 解析时选择一套稳定序列化库并锁定，不同时维护多套。

[Compose](https://developer.android.com/develop/ui/compose/documentation)、[Room](https://developer.android.com/training/data-storage/room)、[Keystore](https://developer.android.com/privacy-and-security/keystore)、[DataStore](https://developer.android.com/topic/libraries/architecture/datastore)、[jsoup 净化](https://jsoup.org/cookbook/cleaning-html/safelist-sanitizer)。加密实现按官方方案和平台 API，不自行设计算法；记录凭据持久化失败时的恢复行为。

| 目的地 | 凭据 | 规则 |
| --- | --- | --- |
| 用户实例 origin | x-admin-secret | 仅此 origin 附带；带凭据请求拒绝重定向，不转发到其他目标 |
| 用户 AI base URL | Authorization: Bearer … | 只发给配置供应商；拒绝重定向，不带实例密钥 |
| RSS/文章/图片原站 | 无 App 凭据 | 仅安全公开 HTTPS；每次跳转检查目标；最多 3 跳 |

用明确的请求函数或隔离 OkHttp client 完成上述规则，不引入多实现工厂。带凭据 client 关闭自动重定向；公开抓取手动验证每一跳。一般 15 秒、AI 60 秒；2026-10-09 RSS慢速下载返修只将本机RSS每跳HTTP请求总时限设为60秒，连接、写入及单次读取等待仍15秒，沿用同一无凭据公开通道和5MiB限额，不增加自动重试。取消时取消请求并校验回包仍归属于原实例/任务。不能仅靠取消 UI 解决跨实例写入。

实例和 AI 地址不允许用户名/密码、片段或 query；实例只接受 HTTPS origin，不支持子路径部署，AI base URL 可含路径（例如 /v1）。生产 TLS 校验不关闭、不忽略证书错误。原生请求不需要 CORS 代理。

UI 随原生 APK 编译安装，不加载远程整站作为 App 首页，不依赖 dist 或 cap sync。WebView 只负责净化正文；实现见第 7 节。旧浏览器预览只能检查旧 Web，不是新客户端验收。

## 3. 后端 API 目标契约

### 3.1 全局约定

- 保留现有 `/api/…` 路径和成功响应主体，不引入 `/v2` 或统一重包所有成功响应。下表是待实现的首版约束，原代码尚未全部满足。
- 所有 `/api/*` 业务请求先校验 `ADMIN_SECRET`。未配置返回 503；缺失/错误请求密钥返回 401。OPTIONS 仅按来源白名单回答预检，不返回业务数据、不代表放行后续请求。
- 所有 API 成功、失败与二进制响应均用 `Cache-Control: private, no-store`；移除公共 `s-maxage`。Android 原生请求不依赖 CORS；浏览器仅允许受控开发 origin 和实际自有前端 origin，不能把 `*` 当权限控制。
- 错误 JSON 保留 `error` 可读描述，并增加稳定 `code`；需要时给 `retryAfterSeconds`。不返回堆栈、SQL、请求密钥或带订阅 token 的完整 URL。状态：400 输入无效、401 未认证、403 目标禁止、404 不存在、405 方法不支持、409 冲突、413 过大、422 非 RSS/不可处理内容、429 限流、502 上游失败、503 未配置、504 超时。
- 拒绝不匹配的方法与未知 action，不能 GET `/add` 意外返回列表，不能 POST `/get` 绕过写入规则。JSON 端点要求正确 Content-Type。生产停用 debug 路由（404），所有媒体代理也在鉴权边界内。
- 首版一般网络超时 15 秒，AI 60 秒；本机RSS下载按上述每跳60秒总时限/15秒连续读取等待执行。刷新不自动无限重试；UI 保留旧内容。请求取消的物理能力在 G1 实测，不能取消时至少丢弃过期回包，禁止写入新实例的数据。

### 3.2 订阅和历史接口

| 方法与路径 | 输入 | 成功响应/规则 |
| --- | --- | --- |
| GET `/api/feeds/list` | 无 | 原元信息数组：id、category、isSub、customTitle；现在也需鉴权 |
| GET `/api/feeds/list/admin` | 无；旧 `admin=true` 可保留但不能影响鉴权 | 完整源数组，含 url、displayOrder、allowedMediaHosts；App 管理与 OPML 使用此接口 |
| GET `/api/feeds/summary` | 无 | `{id, articleCount}` 数组；历史条数不等于未读数，也不证明某日完整 |
| POST `/api/feeds/add` | id、url、category、customTitle、isSub=false；allowedMediaHosts 可选 | `{success:true}`；新 id 且新 URL 才添加；已有 id/规范化 URL 返回 409，不能覆盖 |
| POST `/api/feeds/update` | 现有 id、原 url、category、customTitle、isSub=false | `{success:true}`；id 不存在 404；url 不同 409，提示另建源；仅改名称/分组 |
| POST `/api/feeds/delete` | id | `{success:true}`；不存在 404；确认后删除服务端源及其历史，本地收藏另保留 |
| POST `/api/feeds/reorder` | 非重复 ids 数组 | 保留已有接口并保护；首版不新增拖拽排序 UI |
| GET `/api/feed?id=…` | 已登记源 id；不接受任意 url 替代 id | XML 正文及正确 Content-Type；源不存在 404；超时/过大不能覆盖旧缓存 |
| GET `/api/history/get?id=…&limit=…&offset=…` | limit 默认 100、范围 1–200；offset 非负整数 | `{feedId,items,lastUpdated,total}`；total 为服务端可用历史；排序稳定（发布时间倒序，再稳定 id） |
| POST `/api/history/upsert` | feedId、items | `{success:true,added,total,expired}`；最多 100 条/批，JSON 最多 2 MiB；源须存在；added 为实际插入量 |

Feed id 使用客户端生成的 UUID，服务端验证，兼容已有非空安全 id 不强制迁移。category 为空时“未分组”；名称最多 120 字符、分组 80 字符、URL 4096 字符。首版个人实例上限 200 个源；达到后提示先清理，不以静默丢弃代替错误。allowedMediaHosts 不在普通 UI 中编辑，缺省由现有可信规则生成；任何手动字段也要校验主机名而非任意字符串。

新增源先以“待验证”状态保存在管理 UI，调用抓取端点验证 RSS/Atom。失败的源明确标红且可改用新 URL/删除，不宣称已成功订阅；批量导入同样列出失败但已登记的条目，不静默删除远程数据。不另造一个可抓取任意 URL 的“测试接口”。

HistoryItem 沿用 guid、link、title、pubDate、author、description、content、thumbnail、enclosure、feedTitle。有效日期统一成 ISO UTC 字符串，未知日期保存 null；读取旧数据也做防御性解析。HTML 原文只作为数据，不能在服务端或客户端直接执行。

上游历史实际是“首次保存，冲突忽略”，不是会更新正文的同步服务。首版保留此历史语义，**当前 RSS 的新正文优先于历史快照**；修正插入数量，并确保 guid/link 两个唯一约束冲突都不会造成整个刷新失败。保留当前 60 天按 lastUpdated 清理的语义，仅在写入触发；不是每天完整归档，也不是按发布时间精确保留。来源：[历史 handler](https://github.com/Sallyn0225/gemini-rss-app/blob/36d0fa44aabc8f17c7d2e73ec382124677551262/server/handlers/history.ts)、[Repository](https://github.com/Sallyn0225/gemini-rss-app/blob/36d0fa44aabc8f17c7d2e73ec382124677551262/server/db/repository.ts)。

### 3.3 抓取、全文和媒体

全文顺序（2026-09-30按现有实现明确兜底范围）：已有 RSS 正文 → 用户点击“获取全文”后原生 HTTP 获取 HTML；仅HTTP抓取失败且当前处于实例范围时，使用自有 `/api/article/extract?url=…&mode=raw` 获取HTML → JVM兼容Readability提取与统一净化 → 失败保留原文。直连拿到HTML但解析失败不额外请求后端，本机范围无后端兜底；全过程不调用AI。原生和后端都对字节数、超时、HTTPS、目标和跳转做校验。提取最多 5 MiB；RSS 响应最多 5 MiB；最多 3 次受控跳转。请求的最后目标也需校验，不能只检查第一跳。JVM 提取库（如 Readability4J）在 T12 核对维护/许可/Android 兼容并用中英、图片、表格样例验证；不能把原 npm Readability 直接当 Kotlin 依赖。

后端提取仍受现有允许主机集合限制（登记源主机及经验证的 allowedMediaHosts）。RSSHub 等源的文章原站不一定在集合内；403 时保留 RSS 正文并给原网页入口，不自动扩大成任意域名代理。

拒绝 URL 凭据、localhost、私有/回环/链路本地/保留地址及其 IPv6、混合表示；每一跳均校验。不要把现有 `safeParseUrl` 或 “Workers 应该限制内网” 当成完整 SSRF 防护证明。G2 要核对运行平台的 DNS/出站约束，并用可控测试验证解析到受限地址的域名与重定向会被拒绝；如果无法证明该边界成立，记录发布阻塞，不能静默取消校验或宣称已加固。无需为此搭建另一个抓取服务。

Cloudflare 首版没有媒体代理端点，不为图片新建认证代理。公开 HTTPS 原图须走无凭据、限额、逐跳验证的资源通道；单图上限10MiB（10,485,760 bytes，2026-09-30最终确认，IP01待实施），正文图片、列表缩略图、离线保存与失败重试统一读取PublicFetch.MAX_IMAGE_BYTES。WebView 资源加载由同一边界拦截，禁止漏回默认网络加载而绕过检查。失败显示占位；不把密钥放到 URL、Cookie 或 WebView 请求头。不允许外部 HTML 指定本地文件路径。音视频首版通过原网页播放，不扩展下载器。

已批准返修的全文结果须在统一净化链中仅移除正文开头与文章/提取标题严格匹配的重复标题，正常章节及图片/图注保留；不使用CSS隐藏替代结构修复。RSS只新增条目级image封面识别，不能误读channel图标；网页封面优先可靠og:image，再twitter:image等明确元信息，复用公开地址校验，使用现有thumbnail字段，不新增作者表或媒体代理。网页元信息与署名仍按不可信输入转义，标题文本不当HTML拼入。

正文与封面保存成功且articleId/scope仍匹配后，更新当前纯文本/字数/内容指纹并重新匹配译文缓存；清除失配旧译文，不自动生成。失败保留旧正文与状态，迟到的提取/翻译结果不污染新文章或新范围。历史缓存可在读取时用同一规则规范化，不做全库破坏性迁移；已有主动离线包不因在线提取自动覆写。

## 4. 手机数据与一致性

### 4.1 数据归属

复用`android-native/app/src/main/`已有Room实体/DAO/database，增量修改实际需要的范围字段和查询。使用明确查询和事务；Room是本地唯一结构化数据层，不再叠加通用ORM/同步引擎。以下是逻辑实体，不强制每项建一张表；以最少表满足一致性。

| 数据 | 必要字段/规则 |
| --- | --- |
| 实例配置 | instanceKey、HTTPS origin、显示名、最近连接时间；instanceKey 为规范化 origin 的稳定哈希，换密钥不换 namespace |
| 源目录 | instanceKey字段作为数据范围键使用：本机为Room权威，实例为服务端只读镜像；含feedId/url/名称/分组/验证状态/最后成功时间。本机离线可编辑，实例仍需成功写远端 |
| 文章与快照 | instanceKey、feedId、localId、guid/link、标题、发布时间、源名称与源 URL 快照、正文/摘要、正文来源 rss/extracted/summary（只有摘要、没有正文时记 summary，详情页据此区分显示）、内容指纹、最后访问时间；删源后仍能导出收藏的来源身份 |
| 阅读状态 | localId、isRead、isStarred、状态时间；清理普通正文后仍保留最小文章身份与这些状态 |
| AI 缓存 | cacheKey、数据范围、任务、模型/端点标识、内容指纹、语言、promptVersion、结果、生成时间；不含 Key |
| 普通设置 | DataStore：主题、字号、活动范围、引导状态、上次页面/源/筛选；小量页面恢复状态由SavedStateHandle配合持久化；数据库才是阅读状态权威来源 |
| 密钥 | Keystore 保护的私有凭据密文：按 instanceKey/供应商配置隔离；不进入 Room、DataStore、URL 或导出文件 |

### 4.2 文章身份和合并

1. 在同一数据范围、同一feedId内先按非空GUID匹配，再按安全绝对原文URL匹配；已有记录保持localId。新记录以这两者中可用者生成带类型前缀的稳定哈希，不用标题或数组下标。
2. GUID 为不透明字符串，只去两侧空白、不改大小写。URL 用标准解析消除默认端口、规范主机，保留 path/query；不删除追踪参数以免合并不同内容。
3. 两个标识都缺失的条目跳过并显示“X 条缺少标识未保存”。已有 GUID 和 link 分别命中不同记录时记录冲突，保留原状态、不自动合并删除，界面显示部分条目异常。
4. 先载本地，成功 RSS 合并新内容但保留已读/收藏；再合并历史补缺。历史不得覆盖刚抓到的正文或用户状态。抓取中切换源/实例时回包只能写入请求发起时的 namespace。
5. 用户状态及关联快照在本地事务成功后才显示“已保存”。收藏文章内容更新失败要保留上次可用快照。SQLite 打开/升级失败进入可恢复错误页，不能自动删库重建。

刷新同源并发去重，当前源距上次成功刷新超过15分钟时前台刷新；下拉不受间隔限制。同时最多刷新一个源，不后台轮询全部源。本机只写Room；实例先本地保存，再按既有目标契约尽力写受保护历史，失败标未同步，下次刷新重试，无持久后台任务队列。2026-09-25源码核查原生历史写入仍有缺口，须L07补齐并验证，不能把旧Web写入当原生证据，也不承诺完整归档。

历史按 100 条分页，用户“加载更多”追加；不要循环预取所有历史。2026-10-14日摘要预览按所选日期查询当前范围已保存候选，不受阅读列表首批窗口限制；仍不以 total 或文章数推断某日远端历史已完整。

### 4.3 删除、清理、迁移

- 删除源：本机事务删除本机目录；实例服务端源/历史删除成功后移除镜像。两者都保留收藏及来源URL为“已删除订阅”，普通快照可清除；远端失败不假装已删除。
- 普通缓存最多 2,000 篇或 100 MiB（UTF-8 正文和普通 AI 结果计入），先到上限按最近访问淘汰；避开当前正文和收藏。收藏正文及其译文独立保护；日摘要属于普通缓存。为新写入腾空间失败时保留旧内容并提示，不能因清理删除状态。
- 收藏不自动淘汰。取消收藏后进入普通预算；存储统计区分普通缓存/收藏文本/总数据库估算。首版不是全机磁盘管理器。
- “清普通缓存”不清收藏、状态、订阅或密钥。另有“重置此设备数据”：明确删除全部本地实例/密钥/缓存，不删除云端订阅；二次确认后执行。
- Room当前schema版本以源码和已导出的schema核对，按序增量迁移并验证失败回滚；本次兼容已安装原生包，不回到初建schemaVersion=1。仅真实结构变化才增加版本，不为演示造迁移。
- 无需迁移作者网站浏览器存储。旧 Capacitor 包与新包分开；如果旧包已存用户数据，先盘点和安全导出，未证明迁移成功不能卸载旧包。新装重新配置，禁止将 localStorage 整包复制进 Room，尤其不搬明文 Key。

## 5. AI 请求和结果契约

### 5.1 配置与发送

首版一组配置：HTTPS base URL、模型 id、API Key。base URL 按供应商文档填写，客户端仅追加 `/chat/completions`，不猜测补 `/v1`。模型手动输入即可，不依赖供应商必须有 `/models` 接口。测试按钮明确会发送最小测试文本且可能计费。

手动任务非流式，每次最多一个 AI 请求，timeout=60 秒。重试必须再次由用户触发。未配置、无网络、输入超限时本地拦截；无成功完成状态不写成功缓存。供应商 `finish_reason` 表明长度截断、返回空值或结构不可解析时，提示结果不完整，不能假装完整成功；保留已有成功结果。

2026-10-14增量：AI响应体最多1MiB（1,048,576 bytes），声明长度与未知长度／分块均有界读取；超限拒绝，不关闭TLS或重定向保护。DeepSeek快捷项仅填入`https://api.deepseek.com`与`deepseek-flash`，不自动保存或发送测试。私有Key及其HTTPS origin绑定均为Keystore保护的密文文件，按原子文件读写；向另一origin发送任务时不读取旧Key。旧配置没有绑定元信息时按其已保存端点兼容，后续保存补绑定；变更供应商需当前供应商Key。保存失败恢复旧密文，界面不能显示保存成功；端点／模型仍为非凭据配置，不把Key写进DataStore、Room、缓存键或导出。

任务开始冻结端点、模型、输入、实例和文章集合。原文仅作为不可信数据传入，与任务指令分隔；模型不能指挥应用发请求或调用工具。首版不启用 function calling、远程工具或自动访问模型返回的链接。

### 5.2 翻译

- 固定简体中文；从当前已净化正文按 DOM 顺序提取编号纯文本块，先显示字符数与 RSS/全文来源。最多 20,000 字符，模型更小限制优先；一篇一次请求、不做长文分批、不静默截断、不压缩成摘要。图片和代码块不送翻译，嵌套文本不重复。
- 2026-10-10 已确认返回结构为 `{"segments":[{"id":"catleaf-b1","text":"对应译文"}]}`；严格检查编号集合、唯一性、文本类型与非空值，乱序按编号归位。缺段/多段/格式错误/截断不写完整缓存、不覆盖旧完整结果，不自动重试。
- 结果纯文本转义后由本地模板加在对应原文下面，同一受控 WebView 显示；原文/双语切换不请求，JS 和桥接仍关闭。canonical 原文继续作为全文、字数、搜索、离线与下次翻译输入，显示译文不回写原文。
- cacheKey 包含范围、文章 localId、正文指纹、base URL、模型、目标语言、任务类型与 promptVersion，新 `v2-bilingual` 另含有序文本块指纹（blocks-v1）。复用现有 result 字符串保存编号 JSON，无 Room schema 变化。旧 v1 缓存明确标为整篇旧译文继续读取，不硬拼对应；换 Key 但同端点/模型不使缓存失效。手动“重新翻译”告知会再请求，写盘失败保留旧结果。
- 读位区分原文与双语布局高度；首次插入按比例回退，同一会话切回已看过的模式恢复该模式位置。比例恢复不是精确段落锚点，须以长文、字号和迟到图片的实际操作验证，不以启用 JS 绕过安全约束。

### 5.3 日摘要

- 用户选单源或全部订阅和本地日期；冻结活动范围、本地时区、日期范围、端点／模型及已勾选集合（上限30篇、30,000字符）。范围预览的「清空勾选」仅通过用户操作清空选择，不截断候选。任何逐篇勾选或清空都更新集合归属，旧集合在途缓存读取回包不得恢复旧结果；新集合重新匹配缓存，不删除旧完整缓存或自动请求。全部订阅用内部范围标记，不创建虚拟feed或远端聚合接口。候选查询JOIN当前范围仍订阅的源，先按所选日期筛选；无有效日期文章不加入，且不受列表200篇首批窗口限制。每篇用已取得正文，否则摘要字段；预览逐项标记“正文/仅摘要”。
- 每篇分配只在本次请求有效的来源编号1…N。现有逐行协议增加「主题|」，与「标题|」「概览|」「要点|来源编号|正文」组成可解析结果；客户端映射为title／overview／topic／text／sourceIds。按实际事件输出要点，同事件报道合并并保留对应来源，不把报道差异合成未证实事实。概览不额外加入无法由要点支撑的事实。
- 客户端仅从冻结的编号表生成链接；不使用模型提供的 URL。超范围编号被移除；出现无有效来源的要点，整份标记“结果不完整，来源待核对”，可展示为临时文本但不写成功缓存，重试仍需用户操作。
- cacheKey含活动范围、单源ID或全部订阅标记、日期、时区、按稳定顺序排列的文章身份和内容指纹、端点／模型、语言与promptVersion。新v2结果要求每个要点有不超过40字符的主题；主题与正文完全相同的重复要点合并来源，但不掩盖原要点缺失有效引用。旧v1完整缓存仍可读取，没有主题也不自动升级请求。已生成后新增文章显示「有新增内容」；不自动付费重算。
- 从原调用链移除摘要前的领域分类步骤，不能只是隐藏分类按钮。旧行业标签和多协议设置不出现在首版界面；无需删除所有备用代码。

纯文本翻译、结构化日摘要是目标协议；Kotlin 客户端按此重新实现，原 service 只作协议/行为参考，不保证旧 prompt 已满足。[原 AI 服务](https://github.com/Sallyn0225/gemini-rss-app/blob/36d0fa44aabc8f17c7d2e73ec382124677551262/services/geminiService.ts)。

### 5.4 当前文章AI解读

复用`AiClient`、`AiCache`与`BilingualArticle`文本块，不新增数据库schema。三任务为overview／explain／question，输入包括contentKind、标题及当前净化正文的有序段落；解释再带选中段落ID，问答再带问题。标题／段落文本合计20,000字符、编号输入JSON40,000字符、问题500字符；图片、代码与pre块不参与。仅摘要须明确范围，不为AI任务自动提取全文。

U05原生选文入口：WebView使用本机`TextClassifier`生成`RemoteAction`，通过应用私有、不可变`PendingIntent`交给非导出动态receiver，不新增导出Activity，不通过JS、桥接或剪贴板取选文。选文最多2000字符，意图绑定`localId+bodyHash+scope`；接收时重新核对当前文章／正文／活动范围及原文显示模式，只接受唯一可靠匹配一个原文段落的选文。原文多段、歧义或失配给出段落选择提示；译文不安装选文AI入口，过期意图直接失效，不能打开另一文章任务。选文先打开解释任务，可切问本文；不自动请求供应商，引用继续用原段落ID，模型／接收方／费用提示保持。

为兼容WebView74与143的原生浮动菜单，保留TextClassifier旧主动作字段，并通过`ActionMode.Callback2`仅移除`itemId=android.R.id.textAssist`且标题为「AI解读」的图标，使该项显示文字。RemoteAction名称与此自有菜单匹配同步；创建、准备、点击、销毁与内容定位全部委托原回调，复制／全选及其他系统项保持原行为。取选文仍使用TextClassifier，不读取菜单或剪贴板。旧0.1.26验收中的「AI辅助」名称是历史记录，不改写为新包结果。

原生能力依据：[WebView.setTextClassifier](https://developer.android.com/reference/android/webkit/WebView#setTextClassifier(android.view.textclassifier.TextClassifier))、[TextClassifier](https://developer.android.com/reference/android/view/textclassifier/TextClassifier)、[非导出动态广播接收器与生命周期](https://developer.android.com/develop/background-work/background-tasks/broadcasts)。接口可用不代表不同WebView版本的文字菜单行为已验收，须留实际选文与旧意图失效证据。

输出为严格JSON对象`{text, sourceIds, points:[{text,sourceIds}], notInArticle, background}`，拒绝围栏／尾随内容；答案最多4,000字符、最多8个重点且每项最多1,500字符、背景最多3,000字符、结果文本最多32,000字符。引用必须唯一且全部属于冻结输入；非缺失答案及各重点引用非空，解释须含选中段落引用。`notInArticle=true`仅用于解释／问答且引用与重点为空；背景仅解释任务可有，并单独标注不是本文事实。模型文本用Compose Text呈现，不当HTML、URL或动作执行。

U07只改引用呈现与新请求提示：每个答案／重点的非空sourceIds默认折叠为「查看依据（N处）」，展开显示短标签「标题／第N段」，完整contentDescription说明原文标题／段落；仍把原始ID交既有定位校验，不删除、截断或跨要点合并来源。提示词要求足够支撑事实的最少必要依据，通常1至3段，解析器不因此增加3项硬上限。新问答／解释请求要求在text完整表达、points为空，避免再把同一答案写作重点；内部段落id只放sourceIds，正文用自然语言称呼「这一段」。概览仍保留重点。`article-reading`任务、v2 JSON／promptVersion与现有缓存键保持；解析器继续接受旧合法points，旧完整结果免请求读取并使用折叠样式，无静默删改、自动重算或schema变化。措辞要求是模型提示，不能把单例通过当作所有供应商输出质量保证。

缓存键包含活动范围、localId、文本块／标题指纹、正文类型、base URL、模型、语言、任务与提示版本、模式、问题哈希及选段，U05相关解释／问答任务另含选文哈希，不能把不同选文当作同一缓存。缓存读取不需要Key，不自动补请求。新生成与主动重生才请求；失败、截断、格式／引用错误、落盘失败不覆盖旧完整缓存。ViewModel还核对当前文章、正文版本和活动范围，全文写盘成功后取消旧任务并重新匹配；失败保留旧内容。引用编号校验不能替代对模型回答含义的评审。

## 6. OPML 与状态备份

OPML 为标准订阅交换，不含已读/收藏；状态备份为本产品 JSON 文件。两种入口清楚分开，不称 OPML 为完整备份。

| 项目 | 首版规则 |
| --- | --- |
| OPML 读取 | 最多2MiB，读取时即执行预算；支持UTF-8（可带BOM）与带BOM／明确字节序的UTF-16，严格解码；解析最多2000条，每批最多导入200条并可继续后续批次，不提高活动范围200订阅上限。拒绝DOCTYPE／实体声明、畸形／非OPML根结构，非HTTPS或非RSS／Atom抓取配置标无效；文件超限不开始写入（2026-10-14已批准增量，实施／验收见反馈计划） |
| 分组 | 多级 outline 拼成“父 / 子”一级分组，预览可见；超 80 字符须调整，不能悄悄截断 |
| 去重与导入 | 与目标范围完整源列表及文件内已选项按规范化URL比较，不覆写已有名称；本机事务写入并按网络情况验证；实例串行写远端，超时待确认，重试先核对远端。取消只停后续，已完成保留；已保存但验证失败保留脱敏原因及feedId，重试调用同一源verify，不再次add；后续批次保留之前结果，切范围使旧任务失效 |
| 导出 | 保留真实 URL、名称、分组，正确转义 XML；不导出 AI/实例密钥，提醒 URL 中可能含订阅 token |
| 文件交互 | 导入先验证 Android 的标准文件选择输入；导出使用应用临时目录 + 系统分享/保存，不申请全盘存储权限 |
| 状态文件 | format=`catweb-state`；新导出version=2（§8.5），导入兼容旧version=1/sourceOrigin；10MiB/50,000状态上限不变，超限不得写不完整文件 |
| 状态条目 | feed URL、guid/link、标题/来源名、isRead、isStarred；不含正文、AI 结果或任何 App 密钥 |
| 恢复 | 先完整解析校验和预览；将备份源按 URL 映射到目标实例，缺源需用户确认后沿用订阅导入；对应源创建失败的状态不写入 |
| 合并 | 已读/收藏使用并集合并：任一侧为 true 就保留 true；不会用旧备份取消现有收藏；整批本地状态在事务中写入；第二次恢复结果不重复 |
| 跨实例 | 默认恢复回同 origin；不同 origin 必须明确选择迁移并确认源 URL 映射；不可直接复用旧 feedId/localId |
| 收藏孤立项 | 已删除源的收藏可恢复为独立书签，保留链接和标题；显示“正文未备份，需联网重新获取”，不冒充可离线 |

目标为实例时先远端逐源导入、再本地事务恢复，二者不是跨云/手机原子事务；失败列出远端已完成及本地状态。目标本机时不请求实例，校验/预览后的源及状态合并在同一Room事务内完成。跨范围与兼容细则见§8。

## 7. 正文渲染、恢复与日志

RSS 和提取正文沿同一个 jsoup Cleaner allowlist 入口，解析后移除脚本、事件、iframe、表单、嵌入对象、外部样式和危险 URL；相对链接基于已验证文章 URL 转成绝对链接。明确允许段落、标题、列表、图片、引用、代码和表格；样式由 App 自己的模板提供，不能依赖正则清洗或信任“RSS 自带 HTML”。AI 译文以文本呈现，摘要由校验后的结构化数据渲染。

Compose 外层通过 AndroidView 嵌入正文 WebView。关闭 JavaScript、DOM storage、文件/content 访问、文件跨域访问与混合内容；不注册 addJavascriptInterface，不给正文设置 App 密钥/Cookie。通过 App 控制的 HTTPS 虚拟来源加载模板/净化内容（WebViewAssetLoader 或官方推荐的等效本地内容方式），不直接 loadUrl 打开文章原站。所有正文资源须有明确允许路径，其余拒绝；公开图片沿第 3.3 节受控请求返回受限字节，失败占位。

外链仅接受规范化后的 HTTP/HTTPS，用户点击后交给系统浏览器/Custom Tabs；没有支持程序时给可理解错误。自动导航、弹窗及未知 scheme 拦截；不能把整个外站留在正文 WebView。凭据请求只允许 HTTPS，不因允许用户打开 HTTP 原链接而扩大后台抓取边界。[本地内容加载](https://developer.android.com/develop/ui/views/layout/webapps/load-local-content)、[桥接风险](https://developer.android.com/privacy-and-security/risks/insecure-webview-native-bridges)

AI阅读引用定位只允许当前已加载模板的同origin、同路径及同render查询标识，片段严格为`catleaf-title`或`catleaf-bN`且来自当前有效引用；关闭阅读面板并切回原文后，由WebView本地片段导航滚到标题／段落。不同文档、外站、其它片段一律不能借此留在WebView。保持JS关闭、无桥接，不把模型ID拼成任意导航URL。

列表位置以稳定文章 id + 偏移恢复，不能只记数组序号。正文记录 articleId、内容指纹、排版参数及原生滚动位置；布局就绪再恢复，字号/正文改变时做合理位置回退，不注入 JS 来维持读进度，也不承诺不同排版逐像素一致。进程恢复不得自动重新发送 AI 付费请求。

凭据不进入可序列化 UI 状态、SavedStateHandle 或请求日志。日志仅记录类型、状态码、耗时、脱敏错误及条目数；URL query 视为潜在敏感数据。关闭不受控自动应用数据备份，并核对 Android 版本对应的备份/设备迁移排除规则；密文及其不可迁移材料不能作为普通备份恢复。用户使用明确的状态文件迁移。

上述约束均为实施目标，必须通过 [验收文档](./06-验收与发布.md) 的失败用例；安装库、关闭一个 WebView 开关或仅有测试文件都不等于通过。

## 8. 本机优先增量契约（ADR 003）

### 8.1 活动范围与旧版升级

- 内部使用范围只有本机或一个实例。保留旧实例origin哈希作为key，不重新计算、不改旧localId/feedId/凭据索引。本机使用稳定保留键`local:v1`，不能与实例origin哈希冲突；没有HTTP地址或访问密钥，不为兼容构造假InstanceEntity/假FeedApi。
- 现有实体字段instanceKey可暂复用为scope key，避免无意义全库重命名；逻辑显式区分kind=local/instance。记录活动范围与引导完成状态；需要schema变化时才增加Room版本并写迁移，禁止破坏性迁移。
- 升级时若已有活动实例或旧数据，优先恢复原范围，标引导已处理；不可因密钥暂不可读而创建空范围覆盖。首次全新无数据才选本机并显示引导。原缓存可读，密钥问题走修复提示。
- 选择已保存范围不需联网；添加新实例仍需连通和安全保存成功后切换。每个范围保留源/筛选/列表及读位锚，活动范围切换取消旧UI任务；迟到结果最多写请求发起范围，不能写新范围/更新新界面。旧请求退出验证沿用A12，不只靠取消协程。
- 全局主题/字号及一组AI配置继续共享；AI结果键包含范围，不互相冒用。备份、导入、目录已订阅状态、全文、摘要等所有入口取得同一活动范围快照。

### 8.2 本机抓取与真实提交结果

复用PublicFetch→FeedParser→ArticleMerger→Room及统一净化/正文渲染。PublicFetch是阻塞IO，使用既有调度；仅HTTPS、公开目标、逐跳校验、超时/字节限额和无凭据规则不降。XML按BOM/声明及响应编码处理，覆盖UTF-8和实际非UTF-8样本，不能把所有XML强解UTF-8。URI校验在表单和共享存储入口都生效。

本机源新增先写Room、成功后验证；无网则显示“已保存，联网后验证”，不得标RSS可读。验证失败保留源、失败原因、重试，成功解析后合并文章并更新真实状态。本机编辑/删除离线可完成，写盘失败保持旧状态。实例仍以服务端确认为准，API超时不能断言没有写入。

新增结果需区分登记结果和验证结果，不再忽略refresh/verify失败后统一返回“已添加并验证”。名称自定义优先；来源名称取得前以URL主机兜底。重复点击与OPML/目录共用去重边界。仅scope+规范化源URL重复判已有，同站不同路径/有意义查询保持独立。

本机“加载更多”只翻本地已保存页，没有远端历史时显示“已显示本机保存内容”；实例历史分页保持。全部日期/未读只筛当前已加载集合，不主动抓历史。

### 8.3 全文、AI及实例请求

全文提取器的后端兜底成为可选能力：本机直连→Readability→净化均可独立工作；没有实例就返回本机错误与原网页入口，不要求先连接。实例才允许受保护的原始HTML兜底。图片继续公开通道，密钥不进WebView。

AI的业务条件是配置有效与用户确认，不是currentInstanceKey对应服务器存在。冻结scope key与任务输入，缓存仍按范围隔离；本机与实例均先读成功缓存。实例服务端目录、抓取、历史写入沿用旧契约；本机模式不发实例API、不请求隐藏默认服务。新目录不使用付费AI自动分类。

### 8.4 复制已下载数据到本机

入口仅在活动实例的使用方式页，source固定当前实例，target固定本机；提供选择源与预览已下载文章/已读/收藏/仅书签数量。删除源后孤立收藏作为独立可选组保留。源/文章/状态按现有上限校验，不自动获取更多历史。预览绑定source/target和数据版本；期间变更或切范围需刷新预览，禁止应用旧预览。

规范化feed URL映射到目标feedId，再按源+GUID、其次link匹配；新建目标localId，禁止把旧ID当目标。保留目标自定义名称/分组；新源可沿源分组。已读/收藏作OR合并；已有目标收藏时间保留，否则沿源收藏时间。已存在的目标正文不被源覆盖，目标缺正文才复制来源已缓存净化正文；仅书签如实标识。拷贝来源快照以保留删源收藏。

空间/数量预检查失败停止并提供缩小选择，不静默少复制；写入源、文章、正文及状态使用单个Room事务，失败回滚本机、源实例不动。普通缓存2,000篇/100MiB预算按设备各范围合计，收藏保护不变。不得复制API密钥、实例身份、AI结果；只有映射成功且正文指纹一致才可恢复当前文章读位，否则保留目标原读位并在结果说明。

成功显示新增/已存在合并/仅书签等真实计数，提供“切换到本机”；复制本身不自动切换、不删除远端。重复复制结果幂等；失败可重试。此操作在手机本地完成，不叫云备份或双向同步。向实例迁移继续用OPML/状态恢复，不新造上传所有正文接口。

### 8.5 状态文件v2与兼容

新导出固定`format=catweb-state, version=2, exportedAt, source, feeds, articles`；source为`{kind:local}`或`{kind:instance, origin:规范化HTTPS origin}`。不导出内部scope key或设备标识。其余状态条目字段、限额、无正文/图片/AI缓存/凭据规则不变，导出只针对明确活动范围。

导入兼容v1：将sourceOrigin解析为实例来源，不擅自当作本机；v2校验kind与origin对应关系，未知版本/矛盾字段拒绝，保留用户数据。旧App可能不支持v2，导出页说明“需支持v2的猫页版本恢复”。不要把local:v1伪装成URL写进v1。

预览显示文件来源与当前目标；源本机/目标实例或不同origin都明确提示迁移并确认，URL映射与状态OR沿用§6。目标实例沿既有逐源远端处理→本地事务，部分失败分别展示；目标本机采用单个事务。孤立收藏恢复为书签且明确正文未备份。取消不写入；重试不能重复源或取消原收藏。

### 8.6 内置发现目录

推荐最小目录结构：`catalogVersion, checkedAt, entries[]`。entry包含稳定id、name、feedUrl、siteUrl、categoryId、language、tags、plainDescription、sourceType、status、checkedAt、provenance、可选aliases/configHelp。精选顺序用固定ID列表引用，不复制实体；2026-10-09用户批准原五源后追加橘鸦AI早报，首次引导取原五源。源目录静态资源随APK发版，不建API/运营后台。核查台账与生产entries分开：无效地址不得进入默认可添加列表。

2026-10-09补充：生产entries的feedUrl只能是无用户名/密码的HTTPS；生成器对全部发布项检查，目录核验从HTTPS候选开始，手动检查每次重定向且拒绝降级。HTTP替代经实测和原生RSS解析通过后保留旧稳定ID，originalUrl与核验原因留在台账；未通过项仅待复验。此变更只更新内置目录，不改用户Room订阅、数据库schema或PublicFetch安全限制。

分类固定12ID映射PRD中文名；名称/描述是数据不是执行指令，按纯文本显示。来源URL与RSS内容不同；不依赖第三方“查看”链接作为实际feed。保留查询参数，别名仅在内容核对后合并，不以同名/同域名去重。每条候选最终给出可收录/合并/需配置/待复验/暂不收录及原因，原340快照补五源缺项而非承诺340个可用项。

浏览与搜索均本地，默认不抓favicon或文章；用统一字标兜底。已订阅按活动范围规范化URL/核准别名计算，目录更新不触碰用户的名称、分组或地址。需要配置的RSSHub条目只解释配置并预填，不默默选择陌生公共代理；HTTPS/TLS与所有输出目的地规则保持。

## 9. 文章搜索与离线包增量契约（PRD v3.1）

### 9.1 复用Room搜索

Q01先查询文章标题与纯文本摘要；Q02扩展已保存原文（包括主动离线快照，按localId去重）。查询绑定活动scope与可选feed/日期/未读/收藏；在数据库分页，不取阅读列表的200条内存集合过滤。摘要/正文先按统一HTML处理提取纯文本，不能在每次键入时全库反复净化HTML。

最小实现先用参数化SQL的文字包含匹配；转义LIKE的%/_/转义符，用户输入不是SQL或FTS表达式。关键词最多100字符，去两端空白，ASCII英文不区分大小写，中文连续子串应可命中；不承诺模糊、拼音、繁简转换或分词检索。输入约250ms防抖，后台查询、分页50条，取消或序号阻止旧结果回写。空词不扫描。结果片段作为纯文本着色，不能注入HTML到Compose/WebView。

复用现有Room与SQLite，不为2,000篇常规文本先加搜索服务或分词依赖。若实测包含查询不达标，再在已锁定兼容版本上评估FTS/索引，必须保留中文子串用例；不能把unicode61等同中文分词能力。索引属于派生缓存，正文清理/删除/替换与索引同步，禁止只删除正文却留搜索文本。收藏正文无普通条数上限，需另测大收藏样本，不能声称规模无限。

### 9.2 单篇离线数据与请求

按scope+localId保存最小离线元信息、正文指纹、冻结的净化正文/标题/来源及资源清单；照片等资源使用应用生成的内部ID，不用HTML给出的路径。复用PublicFetch的HTTPS、公开目标、逐跳验证、超时/类型/字节限额与无凭据通道；单图10MiB，声明长度和流式读取均执行上限检查，不扩大请求目标边界。静态正文实际引用的允许图片加封面去重，不沿链接爬取、不下载脚本/字体/音视频/页面附件。

私有离线目录排除系统自动备份，沿已有no-backup与数据迁移排除规则，不把媒体包隐式上传或承诺换机恢复。结果若只命中离线旧快照，显示“离线副本命中”并打开该快照；同文多版本命中只保留一项，优先当前正文，避免片段与打开的内容不一致。

采用每篇私有目录及最小数据库记录即可，不建跨篇去重存储平台。先临时文件、校验成功后原子改名，再记录可用；文件系统与Room不能假称同一事务，启动时核对清单、处理孤立临时文件、将缺文件项降为未齐。写失败不能设置完成；覆盖更新先另存新版，成功切换后才清旧版。预算实际统计正文和图片、含在途临时占用；300MiB为所有scope离线包共用，单篇20MiB/50图，无静默自动删旧包。

正文阅读复用同一净化模板与受控WebView；离线包通过已有受控资源拦截能力映射内部ID→该scope该文章已核验文件，不开放file://或任意content://、不加JS桥。无网只读已保存资源，缺失显示占位；离线包阅读不偷偷回源补图。原内容变化不覆盖已固定快照，需用户重新保存；全文搜索注明命中已保存原文，不声称在线最新。

### 9.3 任务与清理一致性

只执行用户确认的单篇保存，同一文章去重、最多一个运行任务，进行中再启动其他文章时提示稍后重试，不建批量队列。正文成功即成为可读保护项；图片逐个记录成功/失败，失败重试只针对未完成项。取消/离开App或系统终止不保证继续，持久化记录足以在下次进入显示中断与手动重试；不自动启动后台常驻/自动续传。切范围时取消旧任务，已提交结果只归原scope，旧进度不覆盖新页。

收藏保护、普通缓存和主动离线保护分别判断。普通清理不碰离线目录；删源仍保留其离线副本与来源快照。移除离线包不改读/收藏状态，有收藏且无其他正文时先事务保留净化文本，再删除包；失败保留包。设置重置明确包括全部离线包。任务进行中移除同包先取消并等待文件写入停止，再删除，防止晚到写入复活文件。

既有状态文件v2结构不升级：不输出离线文件路径、资源映射或完成标志，恢复不伪装已下载。L05复制不自动复制离线包；仅原既定文章正文/状态，预览标“图片离线包不复制”，目标无已下载标记。旧实例/本机数据迁移沿已有非破坏性迁移。离线包是设备内容，不是备份。


### 2026-10-09 全部订阅与微信样本增量契约

聚合查询JOIN当前范围feeds与articles，并LEFT JOIN正文预览；数据库按日期/未读筛选后稳定排序取有限页，与计数使用相同条件。没有新增Room schema。ReadingUiState显式allFeeds区分聚合/无源；聚合不构造feedId、不调用远端聚合历史。顺序刷新复用单源仓储限流/锁/写盘规则，停止/切源/切范围失效旧会话，旧查询不得缩减已扩展页。普通DataStore增加last_reading_scope_key、last_reading_all_feeds和last_reading_loaded_count，旧键兼容；范围不同的选择和锚点不串用。聚合重开有稳定ID锚点时，以已保存加载数加一页余量恢复查询窗口；该数仅为加载提示，位置仍按稳定ID核对，未命中时沿原规则回顶部，不作为历史条数上限。

2026-10-09 聚合分页返修：200 为首批/每次增加的本地查询窗口，不能作为保存篇数上限。聚合状态保存同条件计数，界面区分已显示与本地符合筛选的总篇数。顺序网络刷新期间仍允许用户加载本地下一页；刷新查询不得解除另一在途分页的加载状态，较小旧窗口不得缩减已扩展页。单源远端历史仍按既有锁与游标规则处理，不循环预取全部历史。

实际Anyfeeder微信RSS把mmbiz.qpic.cn图包在img2.jintiankansha.me/get?src=的HTTP地址里。唯一jsoup入口仅对这个精确代理主机/路径提取原图，并对精确mmbiz.qpic.cn的mmbiz_/sz_mmbiz_图片路径使用核实的HTTPS端点；同样适用于旧在线缓存读取、新RSS/全文、新离线与重试。伪装主机、凭据、端口、内网及其他HTTP源不能套用。最终仍经PublicFetch逐跳校验、无凭据和现有10MiB/20MiB/50图/300MiB预算。旧离线包不自动重写；第三方页尾HTTP资源失败如实部分保存。
