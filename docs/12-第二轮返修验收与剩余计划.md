## 2. 仍需修复或纠正的三项

### W01：V01 短拖动最终位置仍未保存（真机复现，主要）

长滑动 b03→b04 可恢复同段落，但短拖动 b05→b06 失败：正文从“entries. Vary tells…”拖至“Vary support is now available…”开头，停止后等待3秒、截图取证，再 force-stop。重开同文并等待12秒，回到短拖动前的位置，“How Vary works”也明显下移。不是刚好来不及写盘：停止后已经等待数秒。

源码 `ArticleBodyView.kt` 的 OnScrollChangedListener 只有每1秒首沿节流；一次不足1秒的短拖动没有末沿保存，停止后也不会产生新事件。`ReaderViewModel.rememberScrollPosition` 只持久化收到的位置。

最小修复：继续限制写入频率，但补最后位置的延迟保存，取消/释放待执行回调，避免文章切换时把旧位置写给新文章；保留离页保存。不需要新的位置管理框架。

验收：短拖动不足1秒→停止超过保存窗口→强停→重开；连续长滑动、返回、切文章、旋转分别复验。允许既有比例锚的少量排版残差，不允许整段拖动丢失。留下能捕捉末沿遗漏的最小可重复检查。

### W02：V07 命名空间作用域处理不完整（源码确认，运行补验）

`FeedParser` 关闭命名空间处理；`readElementMarkup` 新建空的前缀映射，只记录 content 及其子节点声明，没有继承 feed/entry 的声明。合法输入例如：

```xml
<feed xmlns="http://www.w3.org/2005/Atom" xmlns:x="http://www.w3.org/1999/xhtml">
  <entry><id>scope-test</id><title>scope</title>
    <content type="xhtml"><x:div><x:p>text</x:p><x:img src="https://example.org/a.png"/></x:div></content>
  </entry>
</feed>
```

当前路径不能把 x:img/x:p 还原为白名单标签。另有“映射只增不减”的显式简化，同名前缀在子树改绑后不恢复也不符合输入解析要求。现存测试把声明放在 xhtml:div 上，没有覆盖祖先声明。此项是源码路径结论，本轮未向用户实例添加测试源，不声称真机复现。

最小修复：正确使用解析器命名空间作用域，或在现有解析流程维护作用域；保留 RSS 扩展字段匹配和统一净化入口。补 feed/entry 祖先声明、内层改绑后恢复、默认与前缀、非 XHTML、下一条不被吞的解析→净化检查，再用隔离样本验证设备显示。F19 不依赖 AI Key，不应与收费授权捆绑。

### W03：性能“通过”证据不满足总计划（验收记录问题）

`docs/06` 要求缓存200篇、各20次，启动终点为缓存列表可操作、详情终点为缓存正文可读，排序取第19个样本。现有缓存20篇；冷启动 am start -W 的 Activity TotalTime 不能证明列表已可操作。

`detail-open-bench.py` 在阻塞的 adb tap 返回后 sleep(0.95)，再截屏；没有记录每次点击至正文可读的耗时，截图往返也未计入可解释的时间边界。固定区域灰度/亮像素比例不能可靠区分正文、封面或其他文字，不能由20次布尔值推出 P95≤1秒。

保留原始记录，降级为启动/详情烟测；不是判定实际性能不达标。用隔离的200篇缓存按原定义重新采样，记录每次耗时、起止判据、图像/网络单独耗时与P95；补 V08 长列表内存和请求计数，达到既定上限的 B03 数据规模另外检查。不要引入大型性能平台。
