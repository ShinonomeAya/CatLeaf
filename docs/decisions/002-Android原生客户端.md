# ADR 002：Android 原生客户端，保留轻量后端

2026-09-25补充：[ADR 003](003-默认本地与可选实例.md)将后端连接改为可选、基础阅读默认本机；本决策的Kotlin/Compose路线及安全要求继续有效。下文保留当时决策背景。

日期：2026-09-22。状态：**采用，待实施验证**。用户要求忽略控制投入、优先好用，并授权在重新调研仍支持推荐路线时修改计划。此次复评支持本决策；不代表代码已经迁移。

## 背景

原 [ADR 001](./001-Android与单用户后端.md) 以复用 Web UI、较低实施投入为主。现在 Android 阅读体验优先；已有 T01 源码基线、T02 Capacitor 模拟器 APK 和品牌资源，后端正在出现实施改动。重新比较八个开源项目后，决定更换客户端路线而保留可复用后端。证据与限制见 [复评](../09-原生路线复评与开源对比.md)。

## 决策

1. 主客户端改用 Kotlin + Jetpack Compose；单 app 模块起步，不搭建跨平台、多后端或通用组件平台。拟新增 `android-native/`，旧 `android/` 保留历史。
2. Room 保存文章/收藏/已读/AI 缓存；DataStore 保存普通偏好；Android Keystore 中的加密密钥保护本地 API 凭据密文。OkHttp 控制请求、取消、超时和重定向。
3. Compose 实现导航、列表、表单和工具栏；WebView 只展示统一净化的正文 HTML，关闭 JavaScript 和 JS 桥接，外链隔离打开。
4. 继续修改原项目 Cloudflare Pages Functions + D1 + KV、原 API 路径和数据契约。AI 仍由手机显式调用，不新增 AI 网关或常驻服务。
5. P0 功能、品牌、原型、数据上限和 A01–A14/B01–B06 不变。借鉴阅读器交互，默认不 fork GPL 客户端、不复制其资源。
6. 本决策替代 ADR 001 第 1/6 项及其插件选型；第 2–5 项的后端、数据职责和手动 AI 原则继续有效。

## 代价与验证边界

React 组件不能直接当 Compose 组件复用；需重新实现客户端并验证系统交互、正文兼容和数据库迁移。原 G0 保留为旧包通过，新增 N01/G0-N；旧 APK 不可冒充新路线交付。新开发包使用不同 applicationId 保护旧包与可能存在的数据；不自动卸载、不声称浏览器数据可直接迁入 Room。

原投入估算失效，N01/G1 后重估。性能目标用实际 Release APK 验证，不宣称 Kotlin 必然快于 RN/Flutter/Capacitor。暂不承诺 iOS、后台抓取、多端状态同步或跨源摘要。

## 决策变更规则

实施者按 [计划](../../tasks/plan.md) 推进；具体稳定版本和文件名属于实现细节，验证并记录即可。换后端、取消离线安全要求、扩大 P0 或改回其他客户端框架时必须说明新证据和影响。已授权的本次路线切换无需重复请求确认。
