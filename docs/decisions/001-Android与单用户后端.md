# ADR 001：Android 混合应用与单用户后端

日期：2026-09-22。状态：**客户端路线已被 [ADR 002](./002-Android原生客户端.md) 替代**；保留历史决策原文。单用户 Cloudflare 后端和手动 AI 原则继续有效；旧插件选型不再作为实施要求。产品范围见 [PRD](../03-PRD.md)。

## 背景

用户希望从手机桌面直接进入类似 gemini-rss-app 的 RSS + AI 阅读体验，Android 优先、个人使用。原项目已有 React/TypeScript 阅读界面、客户端 AI 请求、Cloudflare/Vercel 服务端适配，但没有已验证的 Android 打包、本地离线和安全密钥方案。

## 决策

1. 复用上游代码，使用 Capacitor 打包本地 Web 资源。禁止将生产 `server.url` 指向参考网站充当成品。
2. 后端只交付 Cloudflare Pages Functions + D1 + KV；继续使用原 Repository 和 handler 分层。无需自建常驻 Node 服务、账号体系或队列。
3. 单实例单用户，全 API 认证。复用 `x-admin-secret`/`ADMIN_SECRET` 协议并补齐读接口和历史接口；密钥仅用户配置。
4. 手机 SQLite 保存已读、收藏、正文快照、AI 缓存；D1 保存订阅与抓取历史。两者不承担多设备双向状态同步。
5. AI 由手机显式原生 HTTP 调用，首版只保证一个实际验收的 OpenAI Chat Completions 兼容供应商。手动触发、不后台重试付费请求、不经自有 RSS 后端转发 AI Key。
6. 优先已有组件和样式；补手机导航与状态，不做全站视觉重设计。基础原生插件只按已确定能力添加。

## 比较过的替代方案

| 方案 | 本次未选原因 | 重新考虑的条件 |
| --- | --- | --- |
| 只加载作者站点的 WebView | 难以获得独立订阅、可靠离线和自己的数据 | 用户明确只要原站入口 |
| Read You / 全新 Kotlin | 原生基础好，但当前 AI 体验需另做，复用较少 | G1 后仍无法达到手机体验与数据可靠性 |
| FreshRSS / Miniflux 后端替换 | 成熟订阅服务，但需要重新接 API，现有后端可先满足个人场景 | 服务端抓取与多客户端成为核心需求 |
| 自建 AI 网关、多用户平台 | 当前个人使用无此需要 | 明确有多用户和统一额度管理需求 |

详细项目对比见 [调研](../01-开源项目调研.md)，不因未来可能扩展而提前实施替代方案。

## 代价与验证边界

需要维护个人实例、Android 签名和 SDK；WebView 的性能与原生 UI 不同。手机原生 HTTP 不等于网络跨区域可达。离线仅覆盖已保存文本；不打开 App 时可能错过 RSS 已滚出窗口的内容。

安全存储与 SQLite 选用现有社区插件，但官方兼容声明不等于已通过真机验收。G1 验证实际构建与持久化，G2 验证接口权限及数据边界；失败先修正局部实现，不自动改路线。

## 决策变更规则

替换后端平台、改原生框架、增加同步/后台服务、取消离线或弱化密钥保护属于范围变更，应向用户说明原因、影响和替代方案。补丁版本选择、文件拆分、复用哪个现有组件属于实施细节，可自行决策并留下依据。
