# Android RSS + AI 阅读器：开源项目调研

调研日期：2026-09-22。**历史初评，保留当时低投入方案的依据。当前路线已由 [原生复评](./09-原生路线复评与开源对比.md) 和 [ADR 002](./decisions/002-Android原生客户端.md) 替代。** 下文的“当前/本轮”均指首次调研时点，不代表现在的开发状态。

## 1. 需求与调研边界

已确认：希望开发类似 gemini-rss-app 的手机 App；不想每次打开浏览器进入网站；Android 优先，先满足个人使用；本轮只调研、出方案与 PRD。

后续决策更新：用户已选择“原项目二开 + Capacitor Android 混合应用 + 自有轻量后端”，并要求本轮只完成文档，交给其他 AI 实施。本文保留各路线的比较依据；当前实施范围以 [PRD](./03-PRD.md) 和 [交接入口](../README.md) 为准。手动翻译、单源日摘要等细节属于首版规划默认值。

调研选取原项目和五个对照项目，覆盖 AI 阅读、Android 原生、跨平台客户端、自托管聚合服务。功能依据 README、依赖清单和关键源码；未安装、编译或实测这些开源 App。源码存在不代表发布版本已经提供该能力。

## 2. 原项目：实际能力与边界

[gemini-rss-app](https://github.com/Sallyn0225/gemini-rss-app) 是 Web 阅读器，核心组合为“订阅目录 + 阅读 + 日期筛选 + AI 翻译/分类/日总结”。并非现成 Android 项目。

### 2.1 产品设计

| 模块 | 核实结果 | 对手机 App 的意义 |
| --- | --- | --- |
| 订阅 | 站点级目录，支持分层与排序；增删改需要管理员密钥 | 可复用个人实例管理；不是每位访客都有自己的订阅空间 |
| 阅读 | 文章列表、阅读详情、日期筛选、明暗主题 | 与需求贴近，适合移动化改造 |
| AI | 翻译、分类、按日期总结；任务可指定供应商与模型 | 主要复用价值；不需要训练模型 |
| 阅读状态 | 已读标记保存在浏览器 IndexedDB | 已有本地已读能力，但不等于跨设备同步 |
| 全文 | RSS 自带正文优先；公共代理抓取后用 Readability 提取；失败再用自身服务端获取 HTML | App 应优先使用原生 HTTP 或自有服务，减少公共代理依赖 |
| 缓存 | 正文提取有 24 小时 IndexedDB 缓存；文章列表、总结等存在内存状态 | 不能直接承诺“离线启动后所有数据可用” |
| 历史 | 刷新 RSS 后客户端提交历史，后端保存并支持分页；处理器默认保留 60 天 | 不是已核实的全天候定时采集系统，也不是完整永久档案 |
| 账户与收藏 | 所查数据库只有 feeds/history；未见用户、每人订阅、收藏同步的完整数据模型 | 首版宜单用户；收藏和可靠离线保存属于新增工作 |

依据：[应用状态](https://github.com/Sallyn0225/gemini-rss-app/blob/36d0fa44aabc8f17c7d2e73ec382124677551262/lib/AppContext.tsx)、[界面与日总结调用](https://github.com/Sallyn0225/gemini-rss-app/blob/36d0fa44aabc8f17c7d2e73ec382124677551262/App.tsx)、[订阅权限](https://github.com/Sallyn0225/gemini-rss-app/blob/36d0fa44aabc8f17c7d2e73ec382124677551262/server/handlers/feeds.ts)、[历史调用](https://github.com/Sallyn0225/gemini-rss-app/blob/36d0fa44aabc8f17c7d2e73ec382124677551262/services/rssService.ts)、[历史处理器](https://github.com/Sallyn0225/gemini-rss-app/blob/36d0fa44aabc8f17c7d2e73ec382124677551262/server/handlers/history.ts)、[数据库模型](https://github.com/Sallyn0225/gemini-rss-app/blob/36d0fa44aabc8f17c7d2e73ec382124677551262/server/db/schema.d1.ts)。

### 2.2 技术架构

- 前端：React 19、TypeScript、Vite、Tailwind CSS、Radix UI；浏览器端 DOMParser、Readability、IndexedDB。
- 后端：两套部署入口，Vercel + Neon PostgreSQL，或 Cloudflare Pages Functions + D1；Drizzle 处理数据库，Cloudflare 配置还包含用于限流的 KV。
- AI：客户端直接请求用户配置的供应商，支持 OpenAI 兼容、Responses、Gemini、Anthropic 格式。密钥随 AI 设置存在 localStorage，不能把“没有上传自己的 RSS 后端”理解成“没有发送到 AI 供应商”。
- 前后端依赖同源 `/api/...` 路径。将前端文件放入 APK 后必须配置自己的 API 基地址，不能认为原相对路径自然指向远程站点。
- 未在已检索文件树看到 Android/Capacitor 工程或 PWA manifest/service worker 入口；未核实可直接安装为 PWA。

依据：[依赖清单](https://github.com/Sallyn0225/gemini-rss-app/blob/36d0fa44aabc8f17c7d2e73ec382124677551262/package.json)、[AI 请求实现](https://github.com/Sallyn0225/gemini-rss-app/blob/36d0fa44aabc8f17c7d2e73ec382124677551262/services/geminiService.ts)、[全文提取](https://github.com/Sallyn0225/gemini-rss-app/blob/36d0fa44aabc8f17c7d2e73ec382124677551262/src/services/readabilityService.ts)、[公共代理](https://github.com/Sallyn0225/gemini-rss-app/blob/36d0fa44aabc8f17c7d2e73ec382124677551262/src/services/corsProxy.ts)、[部署配置](https://github.com/Sallyn0225/gemini-rss-app/blob/36d0fa44aabc8f17c7d2e73ec382124677551262/wrangler.toml)、[文件树](https://github.com/Sallyn0225/gemini-rss-app/tree/36d0fa44aabc8f17c7d2e73ec382124677551262)。

表中的“未见内置”表示本轮材料未证明具备，不等于不能通过扩展实现。

### 3.1 需要避免的选型误判

1. Read You 的清单中，Fever、Google Reader、FreshRSS 已勾选；Miniflux 专用适配未勾选。不能宣称已有 Miniflux 原生 API 适配；通过兼容协议连接是另一条路线，需要实测。
2. Fluent Reader Lite 与桌面 Fluent Reader 不是同一能力集合，不能把桌面版功能算到手机端。
3. Folo 已有 Android 入口，但本轮未验证全部在线服务能独立部署；直接 fork 不能默认获得完整运行平台。
4. FreshRSS/Miniflux 的服务端更新，与 Android 的后台刷新是两回事；有 API 不等于自动获得手机通知。
5. 一个项目“有缓存”，不等于在飞行模式、进程被杀、重新开机后能完整离线阅读。

## 4. 调研结论

如果目的仅是“更方便进入作者网站”，先考虑桌面快捷方式或很薄的 Android 容器；这能减少入口步骤，但内容、功能和可用性仍取决于作者站点。

如果目的是“自己的 App，保留这套 AI 阅读体验”，优先复用 gemini-rss-app，用 Capacitor 打包本地前端并补齐手机交互、持久化和自有实例连接。它的总体改动小于换成 Flutter/React Native 后重写阅读 UI。

如果“不想维护任何后端”优先级更高，则改选 Read You 本地模式，先直接使用，再评估新增 AI；此时应放弃强行沿用原项目 React 界面的要求。

具体取舍见 [落地方案](./02-落地方案.md)，功能边界与验收见 [PRD](./03-PRD.md)。
